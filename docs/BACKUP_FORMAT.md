# Web 与安卓 JSON 备份格式

本说明来自现有 `web/index.html` 的 `buildBackup()`、`normalizeRows()` 与 `parseBackupText()`，
以及安卓 `Ledger.java`，描述 Web 1.5.8 与安卓 1.2.1 的兼容规则。
安卓核心解析／导出已通过 JVM 测试；系统文件访问和设备迁移仍需真机验收。

## 导出结构

以下全部是演示值，不是真实账目：

```json
{
  "app": "轻记账",
  "version": 1,
  "appVersion": "1.5.3",
  "exportedAt": "2026-10-18T00:00:00.000Z",
  "count": 1,
  "range": ["2026-10-18", "2026-10-18"],
  "records": [
    {
      "id": "demo-record-1",
      "type": "expense",
      "amount": 1250,
      "cat": "餐饮",
      "note": "演示记录",
      "date": "2026-10-18",
      "ts": 1792281600000
    }
  ],
  "config": {
    "lastCat": {"expense": "餐饮"},
    "budgets": {"2026-10": 200000},
    "theme": "system"
  }
}
```

`version` 是备份格式版本，与软件版本 `appVersion` 不同。
安卓当前导出的 `appVersion` 为 `android-1.2.1`，其余主要字段与 Web 相同。指纹开关、迁移状态、指纹数据及系统锁屏凭据均不随备份导出或导入。
`count` 是记录数，`range` 是记录日期的最早、最晚值，空账本导出时为 `null`。
`exportedAt` 是 ISO 时间；记录的 `date` 是本地日历日期，不应转换时区导致日期变化。

## 金额与记录字段

- `amount` 为正整数，单位是**分**，示例 `1250` 代表 12.50 元；预算金额也以分为单位。
- `type` 为 `expense`（支出）或 `income`（收入），不使用负金额表示支出。
- `id` 是合并去重的重要标识，安卓导入、导出时应保留，不能每次重新生成。
- `date` 使用有效的 `YYYY-MM-DD`；`ts` 是记录时间的毫秒值，旧记录可为 0。
- `cat`、`note` 分别是分类与备注；现有导入最多保留 12、40 个 JavaScript UTF-16 代码单元。
- PIN、目录授权句柄和本机快照不会进入此备份文件。

## 现有 Web 导入行为

Web 接受含 `records` 数组的对象，也兼容旧式裸记录数组；可处理文件开头的 UTF-8 BOM。
导入时校验金额、实际日期，跳过坏记录，并预览有效数量。
金额也接受可转换为有效安全整数的字符串；非 `income` 类型归为支出。
缺少 ID 时会生成旧格式标识，单个文件中重复的 ID 会加后缀。
当前没有可用记录时会拒绝导入，因此空账本导出的文件不能作为有效恢复内容使用。

恢复支持合并与覆盖；写入前尝试创建恢复快照。月度预算可从备份配置导入，
不能把导出配置中出现的所有字段都当成已支持自动恢复，尤其不能覆盖设备 PIN 或目录授权。

## 安卓导入与恢复

安卓接受上述对象、裸记录数组和 UTF-8 BOM，金额保持整数分；缺少 ID 时采用与 Web 一致的
UTF-16 FNV/DJB2 标识算法，保留中文及 Emoji，不因跨端重复导入生成全新 ID。
单次文件上限 20 MB，最多 100,000 条；非法记录跳过、重复 ID 加后缀，无可用记录则拒绝恢复。
金额精度、中文／Emoji、旧式标识、非法日期、重复记录、预算与空记录均有核心测试。

导入先展示有效／跳过／新增数量及日期范围。合并只补充新 ID，不替换已有账目和预算；
覆盖在 SQLite 事务中替换账目与有效月预算，失败回滚。两种操作之前都会尝试创建本机快照，
快照失败则停止恢复；PIN、目录授权和设备外观设置保持不变。
不修改原始用户备份，迁移前仍应独立保留一份原文件。
